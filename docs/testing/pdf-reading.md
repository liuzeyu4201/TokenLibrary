# PDF 阅读位置验证

更新：2026-09-27 01:32。覆盖 L08/L09/L22 的阅读位置、来源定位和文件版本隔离；本页将客户端逻辑验证与原生 PDFView 验收分开。

## 已确认并修复的问题

来源链接首次打开第 2 页时，PDFKit 在安装文档和初始页期间发送的页码通知被抑制，资料详情可能仍显示之前的第 3 页。再次前往同一页也可能没有 PDFKit 通知，无法修正进度。现在显式来源定位在安装完成后确认一次，页码前往同时记录实际到达页；纯默认载入不刷新阅读时间。

PDF 保持打开时，另一设备或资料详情手动记录的新位置只改变 metadata，不触发按原件身份加载的任务，原先的继续阅读提示因此不更新。现在位置集合的变化单独刷新建议，保留当前显示页；同一条已忽略的记录不会因后续 metadata 刷新重复出现。

同时收紧版本和生命周期边界：不恢复无 hash 或不同 hash 的旧位置；定位请求消费一次并绑定原件；被替换 PDF 实例、旧安装代次、已关闭阅读器或已切换工作区的迟到事件不写入位置。实现见 [资料库记录](../implementation/catalog-library.md)。

## 原生复测步骤

1. 在隔离验证库打开三页夹具，前往第 3 页，确认资料详情显示本机第 3/3 页；返回含第 2 页来源链接的笔记，打开来源。预期 PDF 显示第 2/3 页，详情本机记录也为第 2/3 页，退出重开仍为第 2 页。
2. 保持 PDF 第 2 页，打开资料详情并手动记录第 1 页，关闭详情。预期显示“手动记录在第 1 页”，当前 PDF 仍为第 2 页。点“保持当前页”，再修改标题等无关信息或等待同步刷新，原记录不重复提示；重新手动记录后可显示新建议。
3. 有第二客户端时，在另一设备记录不同页；当前客户端只出现建议，不强制跳页。点“继续阅读”后显示和本机记录一致；只打开 PDF 而未导航，不应把较新的另一设备记录压成旧记录。
4. 通过测试数据准备旧文件 hash 的位置和来源链接，再更换原件。预期旧页码不自动跳转，明确显示无法匹配版本；旧批注的待核对行为由既有批注验收另行覆盖。
5. 快速切换 PDF/笔记和工作区后检查阅读位置，旧 PDF 的迟到页码事件不得影响新页面或旧库队列。可在已显示页再次点“前往”，确认页面与位置一致；同页没有额外无变化提交。
6. 批注列表放置同页同类和不同页记录，检查编辑、颜色、删除的可访问标签包含页码、类型与摘要，标识含各自批注 ID。实际 VoiceOver、键盘遍历及读屏宣布结果需单独记录；源码标签与单元测试不等同读屏验收。
