## B 组接口与数据实施约束

- 设备 ID 稳定存储；会话只进 Keychain。服务器地址/用户名可进偏好，密码不落普通偏好或文档。
- 本地目录按服务器规范地址、libraryId 绑定，epoch 是库的恢复世代，不是新的用户身份。服务器切换不可把旧队列静默发往新库。
- 演示库与真实库物理隔离。现有遗留库先只读清点，再通过显式迁入/导出保留用户修改，禁止直接删除。
- 首次全量快照固定 atSeq，分页按该快照读取。新增字段以 additive migration 保留旧数据；客户端与服务端迁移分别验收。
- 增量页的内容与游标在一个本地事务中提交；失败重试同页。应用远端变更不能覆盖未提交本地草稿。
- 图片/PDF 是不可变 blob；引用写入必须等 blob 已确认可用。下载到临时文件，SHA-256 验证后原子替换，再索引。
- 每个操作在首次发送前冻结 body/base/operationId；同一次重试保持不变。后续编辑进入另一个操作，只有对应回执可以确认对应内容。
- 以 HTTP 拉取作为收敛依据。WebSocket 是可选通知加速，不能用目前返回 JSON 的 `/ws` 伪称已实现。
- 一个库由一个同步协调器串行改变进度；对不同操作可考虑有限并行文件传输，避免每次键盘输入发起完整同步。
- 备份维护、认证过期、无网络、冲突、服务器恢复，各有不同状态和重试策略。

## 发布门槛

1. 首次安装、升级旧本地库、无网启动、重新登录、切换服务器都有明确流程。
2. 实际 iPhone 与 Mac、真实 PostgreSQL 与文件存储联调；模拟 HTTP 测试不能替代该门槛。
3. 任意可点击操作要么完成并给反馈，要么说明暂不可用及恢复方式，不能是空动作。
4. 没有 P0 资料丢失、错误“已同步”、破坏原件、不可恢复备份问题。
5. 原 F01—F31 与新增 L01—L30 各有结果；新建议若未纳入本次完整范围，应明确列出，不冒充已实现。
6. 不凭通过数或代码行数宣布完成；更新 docs/testing 与 docs/implementation，列明剩余限制。

## 建议暂缓的新范围

EPUB、DOI/ISBN 在线补全、BibTeX/RIS 导入、正式引用样式、智能检索/AI 问答。先用真实书籍 PDF、论文 PDF 和 Markdown 验证主线。它们是待决定的扩展，不影响先修复已有承诺。
