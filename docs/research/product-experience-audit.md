# 产品体验评估与问题清单

日期：2026-09-26。方法：代码走查、隔离自动化测试、构建检查及无凭据公网健康检查。双端真实设备完整验收尚未完成。用户反馈：iPhone 与 Mac 都无法顺利连接，同步缺少清晰提示和重试。

## 结论

问题不止界面提示。界面、队列、文件传输、远端拉取和部署之间没有形成完整用户流程。先确保本地数据不丢、失败可解释、可以恢复，再完善双向收敛；书籍与论文的新数据模型必须建立在这个基础上。

公网健康接口本轮返回 HTTP 200、`ready: true`、`maintenance: false`，说明当时从开发机到当前服务器的基础通路成立；没有尝试真实账号登录或真实数据上传。这既不能证明两端登录成功，也不能判定用户网络正常。macOS 的 HTTP/ATS 配置、设备网络、服务器地址、认证与后续协议仍需分层诊断，不能凭一条 curl 结果宣布问题已修复。

## 同步状态的产品合同

1. **已保存到本机**：数据库与相关文件落盘，不依赖网络；保存失败必须及时可见，编辑器保留内容。
2. **等待提交**：本地还有未确认操作。队列数量是实际操作数，不是随意估计。
3. **连接中/正在提交**：持续展示进度或活动反馈，可取消连接；不得同时发出重复密码登录。
4. **需要重试**：显示原因、下一步以及待提交数量。429/503 尊重 Retry-After；重试同一操作不得换身份或改字节。
5. **需要登录**：只影响云端操作，已下载的资料继续可读写；提供直接重新登录入口。
6. **存在冲突**：本地内容保留，不能伪装成已同步；解决草稿也需要本地持久化。
7. **已同步**：必须包括提交回执、远端增量应用和依赖文件确认；只能报告当前设备已追到某游标，不能宣称离线设备也已完成。

当前尚未达到第 7 项的完整端到端条件，因此本轮界面用“已连接”“本轮提交已处理”，同时保留远端下载未接通的说明。

## 连接排查顺序

地址语法 → HTTP/TLS 可达 → ready/maintenance → 账号认证 → 库身份/epoch → 操作回执 → 远端游标 → 文件校验与索引。每层都要保留可读结果，不把服务器正常和账号正确混为一谈。

- 连接测试只发送健康检查，不发送密码，不改云端文档。
- 登录错误不自动高频重试；取消应中断请求/等待，不能被当成普通失败继续重试。
- 不能通过忽略证书校验“修好”连接；HTTP/HTTPS 配置问题需明确提示并在部署中处理。
- 客户端原有 HTTP 配置两端不同。本轮不把“全局放开网络安全策略”作为修复。Apple 的 ATS 默认要求 URLSession 使用 HTTPS，见 [官方说明](https://developer.apple.com/documentation/BundleResources/Information-Property-List/NSAppTransportSecurity)。

## 已知资料边界

旧本机库中可能包含演示文档、真实修改、其他 server/root 的资料。不能通过清空 SQLite 或自动全量覆盖解决连接问题。本轮保留旧库；正式整库同步前，必须做库身份绑定和明确迁入流程。切换服务器、库 epoch 改变、设备长期离线、已有本机修改，均属于发布阻断测试。
