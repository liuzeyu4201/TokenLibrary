# Markdown 编辑器与保存协议

更新：2026-09-27，实现仍随原生验收修正。入口是 `clients/Shared/EditorWebView.swift`、`editor/src/` 与Core的 `EditorEdits.swift`。

## 用户行为

笔记提供排版、源码、阅读三种模式。Milkdown 负责排版编辑；切换模式前收集最后一次事务。没有编辑时保持原始 Markdown 字节，不因打开或预览重排源码。数学和 Mermaid 资源、字体随应用打包，可以离线预览；语法错误显示原文和错误提示。

归档笔记默认进入阅读模式，原生栏提供“继续编辑”。该动作只恢复当前笔记整理状态，保留 ID、正文及专题其他成员状态。远端归档到达时先收集本次输入，再隐藏编辑面板；搜索不会把归档资料意外切回可编辑源码。

图片经原生桥验证并保存为资料库附件，正文使用相对 `media/` 路径。编辑器通过只读的 `library-asset://local/` scheme 显示附件。浏览器测试的 data URL 图片替身不代表生产存储行为。

## Mermaid异步呈现

排版Mermaid使用Milkdown预览回调完成异步呈现。PreviewPanel会清理并复制返回元素，因此不能在Promise完成后仅修改原holder；当前实现经applyPreview更新，待挂载一帧后核对当前请求标记，已经换语言、替换或删除的节点不接收迟到图。阅读模式的渲染是另一条路径。该修复来自iOS排版实际停绘及同夹具浏览器复现，自动回归覆盖离线SVG、错误恢复与过期结果，原生修复包按[编辑器验证](../testing/markdown-editor.md)单独记录。

## 图片导入与描述

macOS 的 `WKWebView` 由 Coordinator 实现 `WKUIDelegate` 的文件选择回调，通过 `NSOpenPanel` 选择单张图片。回调签名包含 Swift 并发要求的 `@MainActor` completion handler；仅处理当前主页面、可编辑状态和当前窗口。取消、归档或编辑器已被替换时返回空选择，卸载编辑器时取消残留面板。系统面板负责交互，原生附件桥继续执行格式和大小验证，不把文件选择等同于导入成功。

排版模式原先存在两处丢图问题：Crepe 把可选 Markdown title 的 `null` 写入必须为 string 的 caption，解析失败后只留下空段落；在非空文本选区插图时，通用 insert 又将文本段落的 open slice 深度套给原子图片块。本应用为 caption 提供空串默认值，并以 closed Slice 插入图片。图片插入使用独立的撤销边界，撤销图片不连带撤销刚载入的正文；源码模式仍插入普通 Markdown 图片语法。

[images.js](../../editor/src/images.js) 为图片块分别保存 `alt` 描述、caption 说明与 ratio 缩放。新的正文为标准 `![描述](media/原路径 "说明")`，新导入图片默认以文件名作描述，方括号和反斜杠通过 Markdown 转义保留。实际富文本图片使用描述作为可访问标签，没有描述时依次使用说明或“图片”；保留 Crepe 的原有图片、说明、拖动缩放与附件加载视图。

旧版 `![1.00](...)` / `![0.75](...)` 的两位小数 alt 按旧缩放约定解释；有 caption 时用它作为描述，否则使用“图片”，不虚构已丢失的原文件名。新格式只在非默认比例时添加相邻的隐藏 HTML 注释，例如 `<!-- tokenlibrary-image:v1 ratio=0.75 -->`。比例不占用 alt、title 或附件路径。显式的新格式数字描述也可携带比例为 1 的注释，以区别于历史两位小数；整数描述如 `2024` 保持原样。元数据注释只在精确匹配且紧邻图片时消费，不吞掉其他 HTML。阅读预览不显示这些注释。

打开旧图片仅恢复显示，不自动保存或改写原 Markdown。发生实际排版编辑后才按新格式序列化。保存、离开和重新打开继续遵循下面的原生回执协议。

资料来源链接保留文档 ID、页号及文件 hash。排版链接 schema 对 TokenLibrary 内部路由增加限定支持，同时保留上游对其他协议的过滤；HTML 预览仍经过 DOMPurify。原文件变更时，客户端保留引用文字而不直接使用旧页号。

## 本机保存和并发

每个 WKWebView Coordinator 固定绑定创建时的 DocumentStore 和 MarkdownEditSession。切换资料库不能把旧编辑器的迟到消息写入新库。

自动保存消息携带 requestId、实际开始编辑时的 baseMarkdown 和 proposedMarkdown。JS 串行发送保存请求；原生事务读取当前正文后进行三方合并。成功回执带回合并后的正文；若仍有新的本地输入，下一次保存继续使用该输入真实对应的基准。后台同步刷新不能直接盖掉尚未确认或保存失败的正文。

源码输入单独追踪输入法 composition 生命周期。组合期间只保留编辑器内的当前候选，不提交半成品或重新赋同值 textarea；远端刷新暂存，较早保存的回执不能替换组合文字或把远端合并结果冒充为这些输入的基准。compositionend 提交最终文本，后续原生事务按原基准合并；取消候选且没有本地改动时应用延迟刷新。尚在组合中的 flush 返回未保存并提示先完成候选，不误报导出或离开安全。普通英文空格、尾换行和排版端接收同步的序列化规则没有改变。

编辑器不持久化上次模式，初始为排版；旧 `tl:` 块标记或 script/style/iframe 内容会转为源码以保留原文，排版载入失败也转为源码并报错。搜索定位 `tlFind` 则主动进入源码并选中命中词。因此旧笔记与新笔记打开模式不同，需要分别核对内容、搜索来源和错误提示，不能直接归为丢状态。

有正文冲突时，在 SQLite 中保留可恢复草稿及其基准、当前正文和提议正文。后续输入继续更新同一草稿。磁盘等写入失败会显示重试入口并保留编辑内容。只有拿到原生成功回执才显示本机保存成功；它与服务器同步成功分开显示。

导出、打开来源链接和切换便签之前先等待 `tlFlushEdit`：包括图片读取/导入、排版事务以及在途保存回执。失败时不会继续导出一个被误认为最新的旧正文。离开编辑器时保留原 Coordinator 完成最后一次 flush；强制终止进程仍需单独做原生验收，不能仅由该设计推断通过。

## 导入

Core 使用官方 swift-markdown 语法树定位实际图片和音频引用。代码块中的示例不会被当作附件。相对图片/音频在预检后与文档、待提交队列共同落库；普通文件链接保留原地址，不读取相邻配置文件等内容。文件缺失、越界、格式错误会给出原因，避免导入出一篇看似完整但已缺图的笔记。

应用提供单文件导入，以及“含附件的 Markdown（选择文件夹）”，后者在系统文件夹授权范围内选择笔记并读取其媒体。远程图片不自动下载，原始 HTML 内媒体不自动复制；这些情况在完成后明确提示。
