# Markdown 与来源说明导出

日期：2026-09-26。对应 F18、L05、L19、L26；实现位于 `clients/LibraryCore/Sources/LibraryCore/LibraryExport.swift`。

## 外部阅读行为

普通无附件、无来源关系和应用链接的笔记仍导出单个 `.md` 文件。包含媒体或来源的笔记导出 ZIP，包含正文、实际引用的 `media/` 文件和原始 `metadata.json`。

包含来源关系或 `tokenlibrary://` 链接时，额外生成普通 Markdown 可读的 `来源说明.md`，并在导出的正文末尾添加说明链接。说明文件列出摘录时的来源标题、页码、资料标识、文件 hash、原文和自己的评论；原文件已删除或不在当前设备，也可以读取摘录快照。没有摘录快照的旧链接会明确说明没有独立来源记录。说明文件与笔记重名时使用 `_n` 后缀，避免覆盖正文。

导出明确告知：来源 PDF/其他文档没有随单篇笔记复制；`tokenlibrary://` 需要 TokenLibrary 及对应资料库，普通 Markdown 阅读器不能凭该链接打开原 PDF。页码/hash 是摘录时的记录，原件变化后必须核对。网络媒体和普通外部文件链接未被自动下载。没有把应用内跳转宣称为外部通用跳转。

来源说明中的原文和评论使用足够长的代码围栏保存为可读文字，即便原文含 Markdown 图片或三反引号，也不会变成新的附件读取请求。

## 本轮修复

旧版笔记可能保存 `library-asset://UUID` 图片或音频。此前导出仅识别 `media/`，离线导出可能返回没有附件的 Markdown。本轮用统一 Markdown 语法树识别实际媒体引用，在导出副本中将旧地址换成相对 `media/` 路径，打包实际字节；代码示例中的同类字符串不变。重复指向同一文件的引用只带入一份。

正文、元数据和附件列表来自同一份文档读取结果，不再为导出正文重新读取一次文档，避免编辑恰好发生在两次读取之间时产生正文/附件引用不一致。

本次转换只影响导出产物；资料库正文、附件原件、元数据、待同步操作均不修改。找不到必需媒体时仍明确失败，ZIP 仍执行路径、重复条目、大小校验。

## 边界

这是单篇笔记的可读导出，不是完整资料库备份或来源原文件合集。正文里的普通文件超链接可能仍不可用；需要完整保留媒体文件夹和来源说明后再在外部阅读。原生保存面板的取消、失败重试和第三方应用操作由 UI 验收单独记录。
