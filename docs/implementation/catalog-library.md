# 个人资料库实现记录

更新：2026-09-26。代码已实现；Core 测试结果见 [catalog-library.md](../testing/catalog-library.md)。原生界面操作仍需另行验收，本记录不把编译或单元测试表述为完整 UI 通过。

## 已接通的数据与流程

`Catalog.swift` 在现有稳定文档 ID 上保存书籍、论文、笔记、待分类、专题元数据。物理文件类型与资料分类分开；显示标题不改原文件名。书目字段、标签、收件箱、归档、按设备的阅读位置、来源摘录、相关关系均进入既有待同步队列，与 Markdown/PDF 使用同一同步机制。

专题是多对多引用，不复制或移动成员文件。专题归档后从活跃专题收起，归档入口可阅读、打开成员和恢复整理。直接删除专题时，历史版本遗留在其物理文件夹内的直属文件先原子移到上级目录；重名加 `_n`，子孙随原父目录保留。专题恢复不把这些文件重新移回。删除普通文件夹仍按既有递归删除规则处理。专题关系保留以支持恢复，失效关系可单独移除。

资料详情支持保存书目信息、整理完成、多专题归属、归档/恢复、阅读状态、阅读位置、引用笔记、双向相关资料与来源打开。归档资料不能通过资料信息表单悄悄恢复编辑。PDF 来源链接包含稳定 ID、页码和文件 hash；文件变化时上层阅读器可拒绝旧坐标跳转。来源删除、回收站、待下载、文件变化和旧摘录未记录版本分别显示，摘录快照保留。新建阅读笔记与追加摘录支持调用方提供稳定 ID，重试不会重复创建。

## 筛选、排序与检索响应

资料库增加作者、标签完整名称、年份区间、阅读状态、归档状态与本机原件筛选，可叠加分类、专题和全文关键词。所有结构化条件先判断，正文索引命中不能越过作者或年份等限制。同一文档的多专题关系不会展开成重复结果。默认仍包含归档资料；归档、收件箱、继续阅读入口固定的条件不会被弹窗中重复或矛盾的选项覆盖。

排序支持标题、第一作者、年份新到旧/旧到新、最近阅读。未填作者或年份排在后面；最近阅读取各设备最后一次阅读时间，不取最大页码；同值以标题及稳定 ID 保持确定顺序。年份仅接受 1—9999，空值表示不限，缺少年份的资料不匹配年份范围。已有正文或原件与有可搜索文字分别处理，扫描 PDF 不会因无文字层而归入“原件尚未下载”。

筛选弹窗采用独立草稿，应用前校验，取消保留原条件。标签可输入完整名称，最多显示八个匹配建议，不依赖不可清除的长列表。弹窗有重置入口，列表显示已应用条件及清除按钮，零结果也可清除筛选/搜索。

正文索引、覆盖统计、元数据解析、文件可读性检查和排序在后台任务执行；关键词输入防抖 150 ms。结果绑定资料库路径、文档快照与完整查询条件，切换资料库或条件时不会显示迟到的旧结果；取消请求不能发布结果。每项元数据每次扫描只解码一次，排序比较不反复解码 JSON。覆盖提示读取真实本机索引状态，区分待下载、待索引/检查、无文字层 PDF。

## 并发保存与兼容

所有目录元数据修改、阅读位置、专题关系、对称关系删除和追加摘录都在同一 GRDB 写事务中读取最新文档、合并、更新全文索引并写入同步队列，避免读后保存间隔覆盖同步结果。标题改动不会替换正文、PDF 原件、批注或另一设备阅读位置。

资料详情表单保留打开时基线。未编辑时接收最新资料；有输入时保留草稿，保存只提交用户改动的书目字段。其他设备修改不同字段会合并；修改相同字段且值不一致时整次保存失败，表单保持，错误列出冲突字段，用户可明确重新载入最新信息后再编辑。相同结果的并发保存可成功，无变化不会增加本地写入或同步队列。

写元数据时只更新本次改变的字段。未来版本的未知顶层键、阅读位置/摘录中的扩展键、未识别枚举以及未触碰但形状未知的字段都保留。显式清除的可选值不会从旧 JSON 中复活。

跨库关系通过 `LibraryHierarchy.rootID` 检查。真实服务端根目录的父 ID 为空时停在自身，两个不同真实根不会被误判为同一空字符串根。文件显示标题允许标点，实际新文件名会清除路径分隔符和控制字符、控制 UTF-8 字节长度并处理重名。

## PDF 阅读位置与来源定位

阅读器区分默认载入和显式定位。直接打开 PDF 时，只恢复当前设备、当前文件 hash 且在实际页数内的位置；默认显示或恢复本身不写入新的阅读时间。来源链接、全文检索命中、页码前往等显式定位会记录实际到达页，即使目标就是当前页。来源定位请求具有独立 ID，绑定文档 ID、不可变 blob/path 与文件 hash；安装后消费一次，避免旧请求在替换原件后重新生效。

`PDFReadingState` 负责可独立测试的位置选择和建议规则，`PDFKitView` 在文档与初始页安装结束后确认显式定位，避免安装期间被抑制的 PDFKit 通知使显示页与已保存进度不一致。正常页码事件同时核对 PDFDocument 实例、安装代次、所选文档、当前 store 与文件身份，切换文档或工作区后的迟到事件不会更新旧资料。

iOS 的安装完成还需真实窗口附着与非零布局：完成 PDF 内部布局后执行定位，并跨两个主队列观察确认实际 currentPage 与目标一致、viewport 稳定，再确认进度。否则 UIKit 首次布局可能把过早的定位重置到第 1 页。23:57—23:58 最新合并包的原生复测已确认第 2 页来源首次定位成功，详情本机为 2/3，Mac 第 1 页及手动第 1 页记录保留；该限定结果见 [PDF 阅读位置验证](../testing/pdf-reading.md)。

同一 PDF 保持打开时，metadata 中阅读位置变化会更新“继续阅读”建议，不重载原件或自动跳页。仅提示当前文件版本中比本机记录更新、且与当前页不同的其他设备或手动记录；“手动记录”有独立文案。保持当前页会在本次阅读器生命周期内记住该设备、hash、页码与时间组成的记录，其他元数据刷新不会重复提示；新的阅读记录仍可出现。缺少 hash、原件版本不匹配或页码越界的位置不自动恢复或建议，文件版本无法核对时不生成新的无版本进度。

批注列表的页码、编辑、颜色和删除控件具有包含批注 ID 的稳定 accessibilityIdentifier；标签加入页码、批注类型及最多 36 字的摘要，待核对位置明确标记。此处是实现说明，原生读屏与键盘验收仍以实际操作证据为准。阅读回归及原生复测步骤见 [PDF 阅读位置验证](../testing/pdf-reading.md)。

## 验证边界

Core 验证覆盖本机行为，真实双端同步和附件传输证据由同步测试记录维护。专题服务端删除保护由服务端实施补齐，以涵盖旧客户端或另一设备并发新增子项。原生 Mac/iPhone 的表单、弹窗、键盘、VoiceOver 和大字体验收仍需实际操作证据；本文件不将这些标为完成。

## 2026-09-27：详情离开保护、同库候选与失效关系

资料库、Markdown 编辑器和 PDF 阅读器的详情入口现在由 `CatalogInspectorView` 统一提供“完成”。书目表单有修改时，完成、打开相关资料/反链/来源以及保存摘录后的导航都会先询问保存、放弃或继续编辑。保存仍使用字段基线三方合并；年份非法、同字段冲突或 SQLite/待同步队列写入失败时，不执行导航、不清除表单。放弃不会回滚已经成功保存的摘录或整理操作。

未提交的摘录和评论也阻止直接离开。有此类输入时，提示先继续编辑并使用“创建阅读笔记”或“加入所选笔记”保存，或明确放弃未保存输入；关闭详情不会隐式创建阅读笔记。存在未保存输入时，系统交互下拉关闭被禁用，详情提供“完成”提示与上述选择。此保护针对详情生命周期内的未提交输入，不宣称已实现进程退出后的持久草稿恢复。

相关资料、摘录目标和专题候选先按当前祖先链判断所属库。已登记的旧库虚拟根由 `legacyLibraryInventory()` 提供，实际存在的根文件夹仍可解析；未知缺父、循环、已失效祖先和不同库目标不显示。库存只提供明确根身份，候选的实际父子关系仍使用当前文档快照，避免旧库存快照在资料移动后误放行。PDF 阅读器的摘录选择器使用同一规则；Core 提交时继续在事务内校验。

相关资料中的回收站项目和缺失 ID 有可移除入口。默认仍保留关系供还原使用；用户明确移除时，本机事务同时清理正向和旧数据中的反向关系。可恢复的回收站目标保留正文、父目录、名称、回收时间和未知 metadata；已有冻结操作不被改写，清理作为后续操作排队。服务端配套修复允许回收站资料保留原父的 metadata 更新，数据库物理父仍为 NULL，且不允许借此移动、重命名或还原。服务端部署和原生同步验收须单独确认，不能以本机测试替代。

后续原生闭环已完成：同实例验收服务于 00:57 升级后，iOS 在活跃 B 中移除回收站 A 的反向关系并同步，再还原 A 的整个父文件夹，关系未复活，原父目录、回收批次和到期时间保留。限定步骤与数据库证明见 [iOS 回收站关系清理](../testing/ios-related-trash.md)。

摘录未保存提示位于始终存在的摘录区 footer，避免首个评论字符在 Form 顶部插入新 Section 而改变滚动位置。资料详情顶部常驻“保存资料信息”，复用原保存与三方合并逻辑，仅在有效可编辑且有书目修改时启用；长表单不必滚回原保存行。

资料库每行保留独立详情按钮，并增加可见“更多”菜单；它与长按菜单复用同一动作集合，包括整理、归档、移出当前专题以及删除专题。删除继续经过“删除专题，保留资料”的确认，成员与原件保护规则不变。菜单读屏名称包含资料标题，控件 ID 包含资料 ID。
