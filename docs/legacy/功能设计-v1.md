# 笔记软件功能设计

更新日期：2026-09-13  
状态：功能设计 v1.0，供审阅。用户已确认的功能范围与设计默认分别记录；设计默认不代表用户已逐项确认，可在审阅时调整。  
交付原则：所有已确认功能在一个完整版本中设计、实施和验收，不拆成多期交付。  
文档范围：产品功能、使用流程、同步行为和验收场景。技术选型与实现方案另行设计。

## 1. 产品目标

开发一个个人自用的笔记软件，在 iPhone 和 Mac 上创建、整理、阅读和编辑 Markdown、PDF 文档。已有 Linux 服务器保存云端数据，并提供第三方上传入口。

iPhone、Mac 和服务器共享同一套文档库。两个客户端都保存本地副本，断网时仍可正常工作，联网后自动同步。

“三端一致”指同步完成后的文档、文件夹、内容、批注和回收站状态一致。离线期间允许暂时存在差异；新内容和操作进入待同步状态，不设置永久只属于某一设备的文档区域。

## 3. 功能行为规则

本节至第 9 节将已确认需求展开为可评审的行为规则。标注“建议”的细节作为本版设计默认，便于后续实施；这些默认规则尚未逐项获得用户确认，重点汇总在第 11 节。

### 3.1 文档库与文件夹

- iPhone、Mac 展示同一套文件夹层级和文档列表。
- 可以新建、重命名、移动和删除文件夹，在文件夹内新建笔记或导入 PDF。
- 可以重命名、移动和删除文档；重命名或移动不改变文档身份，也不丢失正文、图片关联和 PDF 批注。
- 文档列表展示名称、类型、修改时间，以及必要的下载、保存或同步状态。
- 建议通过名称或修改时间排序。
- 文件夹不能移动到自身或自己的子文件夹内。
- 删除文件夹时，其包含的文档随文件夹进入回收站；恢复时保留层级关系。

同名上传使用的自动编号规则，不直接代替普通重命名规则。建议手动重命名发生重名时提示用户调整名称，避免名称被意外更改。

### 3.2 Markdown 笔记

- 可以创建空白笔记，也可以导入已有 Markdown 文件。
- 正常编辑采用直接排版的方式，正文内容保持可导出为 Markdown。
- 输入后自动保存到本机；联网时自动提交同步。
- 支持插入图片。离线插入的图片先在本机保存，恢复网络后与笔记一起同步。
- 图片与正文应作为关联内容处理：其他设备应能识别图片是否尚在下载，不能把下载未完成误报为图片丢失。
- 接收其他设备的修改时，应保留当前正在输入的内容；产生冲突则进入冲突处理流程。
- 已确认支持 Mermaid 流程图和 LaTeX 数学公式，具体使用规则见下文。
- 常规排版默认覆盖标题、加粗、斜体、列表、引用、链接、分割线、代码块、表格和任务清单。

**Mermaid 流程图**

- Markdown 中可插入 Mermaid 图表块，编辑图表源码后显示流程图。
- 建议阅读时显示图形，点击编辑时显示源码及预览，与直接排版的正文编辑方式配合。
- 原始图表源码作为笔记内容保留，随正文一起保存、同步、处理冲突和导出。
- iPhone 和 Mac 均应支持离线编写、修改和显示流程图，绘制过程不依赖联网服务。
- 语法错误时显示具体提示并保留源码，允许继续修正，不丢弃内容或阻止整篇笔记保存。
- 当前明确要求为 Mermaid 流程图，其他图表类型尚未列为必须支持的范围。名称和流程图语法参照 [Mermaid 官方流程图文档](https://mermaid.js.org/syntax/flowchart.html)。

**LaTeX 数学公式**

- 支持在 Markdown 正文中编写并显示 LaTeX 数学公式；具体支持的公式语法范围在技术方案中明确。
- 建议同时支持行内公式和独立公式块，分别采用 `$...$` 和 `$$...$$` 标记保存。
- 建议阅读时显示排版后的公式，编辑时可修改公式源码并查看结果。
- iPhone 和 Mac 均应支持离线编辑与显示，原始公式源码随笔记保存和同步。
- 公式语法错误或不受支持时，保留源码并明确提示，不能静默丢失公式。

### 3.3 PDF 阅读、高亮与批注

- 可以导入或通过外部接口上传 PDF，打开后阅读并定位页面。
- 支持文字高亮和文字批注，可查看、新增、修改和删除文字备注。
- 不支持手写批注。标注工具按高亮与文字备注设计，不额外扩展绘图工具。
- 支持修改、删除已有高亮和批注，离线操作同样保存在本机并等待同步。
- PDF 原文件与批注分别记录，便于合并来自两台设备的批注；导出时将批注写入导出的 PDF。
- 对同一份 PDF 的不同批注，可以分别同步和合并。
- 替换 PDF 原文件后，已有批注不能直接假定仍对应相同页面和位置，应提示检查。建议将原文件替换与批注位置不兼容的情况纳入冲突处理。
- 扫描版 PDF 仍可阅读和添加适用的批注；不做 OCR。没有可选文字的位置，不能使用依赖文字选择的高亮方式。

### 3.4 全文搜索

- 搜索范围包括文档标题、Markdown 正文，以及 PDF 中已有的可提取文字。
- 搜索结果显示文档名称、所在文件夹和匹配摘要；打开后定位到对应内容或页面。
- 扫描件只参与标题等已有信息的搜索，不识别页面图片中的文字。
- 回收站中的文档默认不出现在正常文档库的搜索结果中。
- 已确认在线、离线都在各自设备上查询本地索引；本地编辑和同步更新后自动更新索引，已保存在本机但尚未上传的修改也参与本机搜索。
- 新导入或刚同步的 PDF 完成下载和文字索引后参与正文搜索；尚未完成时显示待下载或索引处理中，并展示进度。
- 两端处于不同下载、索引或离线编辑进度时，搜索结果可以暂时不同。

### 3.5 账号与登录

已确认：软件仅供个人使用，预先设置一个固定账号和密码，iPhone 和 Mac 使用同一账号访问同一套文档库。不提供注册入口或多用户管理功能。

已确认的保持登录规则：

- 首次输入固定账号密码时联网验证，成功后记住登录状态，后续联网使用时自动续期。
- 连续 90 天未连接服务器，或主动退出、登录凭据被撤销后，恢复云端访问需要重新登录；90 天按服务器最后一次成功认证的访问时间计算。
- 登录过期仍可阅读和编辑已保存到本机的文件，文档及未上传修改继续保留；重新登录后继续同步。
- 已登录且已下载文档的设备断网后仍可正常使用，不要求每次打开应用都联网验证。

具体账号、密码及配置方式在部署时确定；本功能设计文档不记录实际凭据。第三方上传使用独立 API Token，见第 7.4 节。

### 3.6 服务器自动备份

- 已确认每天自动备份一次服务器数据库、PDF 和图片，保留最近 7 天的成功备份。
- 已确认默认每天北京时间凌晨 03:00 开始备份，允许通过 `.env` 调整执行时间。
- 已确认备份存放在现有 Linux 服务器的独立目录，路径通过 `.env` 配置，具体值部署时填写。
- 备份以服务器已接收的数据为准，包含文档正文、文件夹、PDF 批注、同步记录及对应文件，用于文档库恢复。
- 已确认备份期间暂停云端文档写入；客户端继续本地阅读、编辑并保存待同步修改，备份结束后自动继续同步。第三方 curl 上传在暂停期间需稍后重试。
- 建议每次备份完成后检查完整性；失败时记录错误，不用失败或不完整结果替代已有成功备份。已有备份仍按自身 7 天期限清理，不因新备份失败而延长保留。
- 调度实现、错过执行时间的处理、故障后的恢复操作及客户端重新同步规则在技术方案中细化；不新增面向用户的逐篇笔记历史版本恢复入口。

## 4. 本地副本与自动同步

### 4.1 基本规则

建议两个客户端默认同步整个文档库，包括 Markdown、关联图片、PDF 和批注。文档完整下载后，才具备完整的离线使用条件。

- 首次使用、新设备登录或首次同步时，显示下载进度；尚未下载的文件应明确标识。
- 客户端打开并联网时，自动发送本地修改、接收服务器更新。
- 恢复网络后，自动继续未完成的操作，无需用户逐个上传文件。
- 应用在前台运行且联网时及时同步；iPhone 进入后台后利用系统允许的机会尽力同步，再次打开或恢复前台时自动检查并补齐。后台完成时间不作即时保证，待同步修改保存在本地；具体前台同步时延指标在技术方案中确定。
- Mac 应用运行且联网时继续同步；休眠或应用退出期间的变化，在恢复运行后检查并补齐。
- 显示至少以下状态：已保存到本机、等待同步、同步中、已同步、同步失败、存在冲突。
- 只有服务器确认接收，才可以显示已同步；本地保存成功不能替代服务器确认。
- 一台设备离线或关机时，不宣称该设备已获取最新内容。

### 4.2 离线操作

已下载的文档支持离线阅读、编辑、批注、重命名、移动、删除和导出。也可以离线创建笔记、插入本机图片、导入 PDF、创建文件夹。

离线修改应在本机持久保存，退出或重启应用后仍保留。未同步内容应有清楚状态，恢复联网后自动继续同步。

### 4.3 同步过程中的一致性

- 同一文档通过稳定身份关联，不能仅凭文件名判断是不是同一篇文档。
- 改名或移动后，另一端针对同一文档的正文修改仍应关联回来。
- 第三方上传的新文档进入同一套文档库，并自动同步到客户端。
- 失败重试不能重复创建文档、文件夹或批注。
- 同步中断后可以继续，不能让半个文件被当成完整文件打开。
- 搜索结果、文件夹位置、回收站状态和批注，均应随对应数据更新。
- 设备长时间离线后重新连接，不能因为携带旧副本就静默恢复已删除文档，或覆盖较新的修改。

## 5. 借鉴 Git 的冲突处理

### 5.1 合并依据

比较三个版本：本地修改所基于的共同版本、本地当前内容、服务器当前内容。能合并的修改自动合并，不能合并的部分由用户处理。

Git 的普通三方合并适用于文本；二进制文件需要另行定义合并规则。这里借鉴其处理方式，不据此确定实际采用 Git 仓库作为存储或同步实现。[参考：Git 官方文档](https://git-scm.com/docs/gitattributes#_performing_a_three_way_merge)

内部保存合并所需的基准版本、修改关系和待处理内容，不因此增加面向用户的历史版本恢复功能。若无法取得合并基准，应保留双方修改并提示处理，不能猜测合并结果。

### 5.2 不同对象的处理规则

| 对象或情形 | 建议行为 |
| --- | --- |
| Markdown 两端修改不同且兼容的内容 | 自动合并并同步 |
| Markdown 修改存在冲突 | 展示源码差异，由用户处理冲突部分 |
| 同一 PDF 版本上新增不同批注 | 合并新增批注 |
| 同一条批注被两端改成不同内容 | 保留双方修改，提示选择或重新编辑 |
| 一端删除批注、另一端修改该批注 | 作为冲突处理，不静默丢弃修改 |
| 同一 PDF 原文件被两端替换 | 保留双方版本待选择，不进行文本式合并 |
| 一端改名、另一端编辑正文 | 文档身份保持一致时合并这两项操作 |
| 两端将同一文档改为不同名称或移动到不同位置 | 提示选择最终名称或位置 |
| 一端删除、另一端修改文档 | 展示删除与修改的冲突，由用户决定 |

### 5.3 Markdown 冲突界面

- 展示本机和服务器的源码差异，并可查看共同基准。
- 明确标出冲突位置，支持逐处采用一侧内容或手动编辑合并结果。
- 提交前可以预览合并后的排版效果。
- Mermaid 图表与 LaTeX 公式也按其 Markdown 中的源码参与合并；预览时应能看到图表、公式的显示效果或语法错误提示。
- 未处理完的内容保存在待处理状态，不作为已完成合并的正文发布。
- 合并完成后生成统一结果，同步到各端。
- 若处理过程中服务器内容再次变化，应重新校验并合并，避免使用过时结果覆盖新的修改。

建议 iPhone 和 Mac 都能处理冲突：Mac 适合并排比较，iPhone 按冲突段落逐项处理。待处理冲突本身也同步到服务器，方便在另一台设备继续处理。

上传同名文件与同一文档的编辑冲突是两类事情。前者创建带数字后缀的新文档，后者挂在原文档的冲突状态下，不默认制造多个普通文档副本。

## 6. 回收站与 30 天保留期

- 文档或文件夹删除后进入回收站，从正常文档列表移除。
- 回收站显示名称、原位置、删除时间和剩余保留时间。
- 保留期内可以还原；原文件夹不存在或恢复时重名，建议提示选择位置或调整名称。
- 每项内容进入回收站后保留 30 天，到期从正在使用的文档库永久删除；旧备份的保留边界见下文。
- 建议以服务器确认删除的时间作为统一计时起点；离线删除尚未上传时显示待同步，避免客户端时钟差异影响期限。
- 到期清理由服务器统一确认，客户端联网后清理对应本地副本。离线设备上的文件无法被服务器即时清理。
- 永久删除后再次上线的设备若带有针对该文档的未同步修改，建议进入待处理状态，由用户决定是否另存为新文档；不自动复活原文档。
- 为防止旧设备重新上传已删除内容，可以保留必要的删除标记；删除标记不包含可恢复的文档正文。

已确认的备份边界：回收站到期后从正在使用的文档库清除，新备份不再包含这些内容；已有备份按自身 7 天保留期到期清理，因此旧备份内可能额外保留该文档最多 7 天。备份到期清理不以当天新备份成功为前提，具体执行设计见技术方案第 3.2.6 节。

## 7. 第三方上传

### 7.1 使用流程

第三方程序通过 curl 上传文件，服务端校验后创建文档，返回结果；客户端在线时自动接收新增文档，离线时在下次连接后同步。

建议允许指定目标文件夹；没有指定时放入统一的默认导入位置。上传入口与客户端导入遵循相同的文件类型和大小规则。

### 7.2 同名规则

同一文件夹已存在同名文件时，新上传文件添加 `_数字` 后缀，数字逐次增加，保留扩展名和原文件。

示例：已有 `报告.pdf`，下一份保存为 `报告_1.pdf`，再下一份保存为 `报告_2.pdf`。生成的名称必须仍然可用；同时上传时也不能互相覆盖。

自动重命名只改变新文档的名称，不修改原文档。上传成功结果应包含最终文件名、文档标识和所在位置。

### 7.3 建议的接口行为

- 成功或失败都返回明确结果，失败时提供原因。
- 上传中断或失败不能产生可见但无法打开的半成品文档。
- 同一个上传请求重试时，建议识别为同一次操作，避免生成重复文档。
- 超过允许大小、格式不受支持、目标文件夹不可用时，应明确提示。

### 7.4 上传认证（已确认）

- 第三方程序使用独立的 API Token 调用上传接口。
- 该密钥仅允许上传文件，不授予读取、修改或删除已有文档的权限；同名上传仍创建带数字后缀的新文档。
- 上传密钥可以单独更换或停用，客户端继续使用固定账号密码登录。

本文件定义接口使用效果，具体路径、参数、凭据配置细节和可运行 curl 示例留到技术方案中确定。

## 8. 导出

- Markdown 可导出为 `.md` 文件。
- 导出时保留 Mermaid 源码块及 LaTeX 公式标记，便于再次编辑；软件外的显示效果取决于阅读器对相应语法的支持。
- 建议含有本软件保存图片的 Markdown 同时支持导出正文与图片的打包文件，并整理图片引用，保证在软件外仍可阅读。
- PDF 导出时包含用户的高亮和批注。
- 导出使用用户选定的当前内容；若仍有未处理冲突，应明确提示，不能把未完成的合并误当成最终结果。
- 已完整保存到本机的内容可离线导出。
- 用户主动导出的文件属于文档库之外的独立副本，不参与三端自动同步；在软件外修改导出文件，不自动改变库内文档。

## 9. 主要界面与流程

| 界面 | 核心内容与操作 |
| --- | --- |
| 登录 | 输入预设的固定账号和密码，不提供注册入口 |
| 文档库 | 文件夹导航、文档列表、新建、导入、改名、移动、删除、同步状态 |
| Markdown 编辑器 | 直接排版编辑、插图、Mermaid 流程图、LaTeX 数学公式、保存状态、导出、冲突入口 |
| PDF 阅读器 | 阅读定位、高亮、文字批注管理、同步状态、导出；不提供手写批注入口 |
| 搜索 | 输入关键词、查看匹配摘要、打开对应文档或位置 |
| 回收站 | 查看删除内容、剩余保留时间、还原 |
| 同步与冲突 | 查看待同步、失败、待处理冲突，重试或进入合并界面 |
| 设置 | 查看当前账号、服务器连接及同步状态；具体内容在界面设计中细化 |

两端适配各自屏幕和操作方式，但保持文档能力及同步规则一致。视觉风格和详细布局另行设计。

## 10. 完整交付的验收场景

以下场景基于当前功能范围与设计默认，用于评审和后续验收；如果审阅时调整规则，对应验收场景一并更新。

1. Mac 创建多级文件夹和 Markdown 笔记，插入图片；iPhone 同步后能看到相同层级和内容。
2. 两端完成本地下载后断网，仍可阅读和编辑文档、批注 PDF；退出并重新打开应用后，修改仍然存在。
3. 恢复网络后自动同步离线新增、编辑、移动和删除操作，最终三端一致。
4. 两端修改同一篇 Markdown 的兼容内容后自动合并，不丢失任意一端修改。
5. Markdown 出现冲突时能查看源码差异、处理冲突并同步统一结果；未处理冲突不会被标记为同步完成。
6. 两端对同一 PDF 添加不同高亮和文字批注后可以合并，导出 PDF 能看到对应批注；阅读器不提供手写批注入口。
7. 同一条批注发生矛盾修改、PDF 原文件同时被替换时，不静默覆盖任意一端内容。
8. 重命名、移动文档后，其正文修改、图片及批注仍属于同一篇文档。
9. Markdown 和包含文字的 PDF 可按正文搜索；扫描件不触发 OCR。
10. 文档删除后进入回收站，在保留期内可还原；服务器到期清理后，客户端联网完成对应清理。
11. 长期离线设备重新连接时，不能静默恢复已永久删除的文档或覆盖较新内容。
12. curl 上传的新文档出现在两端；同名上传形成 `_1`、`_2` 等名称，原文件内容保持不变。
13. 上传或同步中断后可继续或重试，不产生重复文档及可见的损坏文件。
14. Markdown 和带批注 PDF 可以导出，并能在软件外检查内容是否完整。
15. 在 1000 篇以内、单个 PDF 不超过 50 MB 的设计规模下，完成导入、阅读、搜索和同步验证；具体性能指标在技术方案中制定。
16. iPhone 和 Mac 使用同一套预设账号密码登录同一文档库，无注册入口；已登录并下载文档的设备断网后仍可正常使用。
17. 在两端分别创建和修改含 Mermaid 流程图、LaTeX 公式的笔记，在线和离线均能编辑并显示，恢复网络后内容一致。
18. 导出再导入含流程图和公式的 Markdown，源码和含义保持一致；发生语法错误或同步冲突时，原始内容仍可查看和修正。
19. iPhone 存在待同步修改时进入后台，即使系统未提供足够执行时间，修改仍保存在本地；再次打开或恢复前台且联网后自动继续同步，未完成的上传、下载及冲突不能被误标为已全部同步。
20. 第三方程序持有效上传 API Token 可上传文件；缺失、无效或已停用的密钥不能上传。上传密钥不能读取、修改或删除已有文档；更换上传密钥不影响客户端账号登录。
21. 首次登录后再次打开应用无需重复输入密码，正常联网访问可续期；连续 90 天无成功认证的访问后，云端访问要求重新登录，本地文档和未同步修改仍保留且可读写。重新登录后继续同步；主动退出或凭据被撤销后，旧凭据不能继续访问云端。
22. 在线、离线均通过本机索引搜索；断网编辑 Markdown 后，索引更新能查到未上传的新内容。curl 上传的 PDF 完成客户端下载和索引后可按正文查找，处理期间显示进度；文档修改或删除后更新对应搜索结果。
23. 服务器按每日计划生成包含数据库及对应 PDF、图片的完整备份，并执行最近 7 天的保留规则；在隔离环境恢复后检查正文、目录、批注和文件引用是否完整。备份失败时记录错误，保留尚未到期的已有可用备份。
24. 备份期间，客户端本地阅读和编辑保持可用，新增修改显示待同步；云端写入及第三方上传不会被误报成功。备份结束后客户端自动继续同步，第三方重试上传可正常完成，已保存的本地修改不丢失。
25. 回收站到期清除文档后，新备份不包含已清除内容；旧备份按自身 7 天期限清理，其中的旧副本额外保留不超过 7 天。新备份失败时，过期备份仍按期清理。
